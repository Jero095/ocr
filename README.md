# Statement Reader

Reads commission statements from insurance carriers — PDFs and CSV/TSV exports —
pulls out the transaction table, **checks the figures against the statement's own
declared total**, and exports to Excel or TSV.

Built because the source PDFs are frequently unusable: many are rotated so that
copy/paste produces scrambled text, and a third of them are scans with no text
layer at all.

## What it does

- **Reads 47 carriers** from one generic layout engine, not 47 hand-written
  parsers. Column boundaries are derived from the geometry of each page.
- **Reads scans too.** 21 statements are image-only; OCR turns them into the same
  word boxes the digital path produces, so everything downstream is identical.
- **Checks itself.** Every export is reconciled against a figure sourced outside
  the table — the amount in the filename and any labelled total in the statement
  text. Figures that do not reconcile **cannot leave the app**: export is blocked
  in the UI and returns 409 from every endpoint.
- **Cleans CSV exports** — dates to `mm/dd/yyyy`, amounts to `.` decimal and `,`
  thousands, with every change reported rather than applied silently.
- **Lets you fix the table** before exporting: edit cells, rename, reorder and
  delete columns, delete rows, restore the original.
- **Lets you crop the page** the parser reads, for statements that bury the table
  in letterhead.
- **Keeps history**, attributed to whoever uploaded each statement.

Current coverage is measured, not claimed — see [CARRIERS.md](CARRIERS.md),
regenerated by a script that sweeps every real statement.

## Running it

```bash
pip install -r requirements.txt
python -m uvicorn app.main:app --reload --port 8000
```

OCR needs the Tesseract engine, which pip cannot install:

```bash
winget install UB-Mannheim.TesseractOCR
```

There is no signup form. Create the first account from the command line:

```bash
python scripts/adduser.py add you@example.com --name "You" --admin
```

Then open http://localhost:8000.

### In a container

```bash
docker build -t statement-reader .
docker run --rm -p 8000:8000 -e PORT=8000 -v "$(pwd)/data:/app/data" statement-reader
```

The volume is not optional — without it every restart loses the history **and
every account**. See [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md).

## Checking a change

There is no unit-test suite. Correctness here means "does this pull the right
numbers out of 58 real carrier documents", which is an integration property over
real files. Three scripts sweep them and print measured results:

```bash
python scripts/carriers_report.py    # per-carrier status; regenerates CARRIERS.md
python scripts/failsafe_report.py    # per-file payout reconciliation
python scripts/ocr_report.py         # OCR settings vs the scans (slow)
```

Run the first two before and after any parsing change and diff the output. The
honest limitation: the fixtures are real client statements, so they are
gitignored and these checks cannot run in CI.

## A warning about the data

`statements/` and `data/` hold real customer names, policy numbers and payment
amounts; `data/` also holds password hashes. Both are gitignored, excluded from
the Docker build context, and must stay that way.

The app has no public exposure by default — it is reached over a private
Tailscale network. See [docs/TAILSCALE.md](docs/TAILSCALE.md) (Spanish).

## Known limitations

- **4 scanned carriers extract figures that do not reconcile** and are blocked
  from export. That is the check working, not a crash — OCR misreads digits.
- **`ISC 58.65.pdf` cannot be opened at all** (reports 0 pages); it needs
  re-exporting from the carrier.
- **No backups.** `data/` is the only copy of the history and the accounts.
- **No rate limiting** at the edge, and no MFA. The login is sound for a small
  known team but has never faced the open internet.
